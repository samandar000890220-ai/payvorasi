# PAYVORA — COMPLETE INTERACTION IMPLEMENTATION CONTRACT

You are implementing the Payvora application from an existing UI and a completed read-only button audit.

## NON-NEGOTIABLE RULE

Do NOT redesign the existing UI.

Do NOT remove, rename, relocate, or visually restyle controls that are already functioning correctly.

Do NOT replace working behavior with new behavior.

Your job is to make every currently inert, stubbed, partially functional, or incorrectly wired interactive control behave according to its intended purpose.

Use the existing UI, components, styling, routes, state architecture, and design language wherever possible.

---

# 3. IMPORTANT ELEVENLABS CORRECTIONS

Do NOT hard-code the previously suggested Speed range of 0.5–2.0.

Current ElevenLabs documentation describes Speed as:

* Default: 1.0
* Minimum: 0.7
* Maximum: 1.2

The UI must therefore use the actual supported range for the selected model rather than blindly assuming 0.5–2.0.

ElevenLabs also documents:

* `stability`
* `similarity_boost`
* `style`
* `use_speaker_boost`
* `speed`

as voice settings, with model-specific availability.

The application must verify compatibility for the selected model before sending unsupported parameters.

Do not silently send unsupported parameters.

# 23. ERROR HANDLING

Implement meaningful user-facing errors.

At minimum handle:

### 401 / 403

Authentication/authorization problem.

Do not expose secrets.

### 422

Invalid request/input.

Show the specific actionable validation problem where available.

### 429

Rate limit.

Tell the user the request was rate-limited.

### 5xx

Provider/server failure.

Allow manual retry.

### Network failure

Show an offline/network error.

### Timeout

# 30. ACCEPTANCE CRITERIA

Do not consider a control implemented merely because clicking it changes React state.

A control is COMPLETE only when its intended user-facing result actually occurs.

For example:

```text
Generate Speech
```

is NOT complete if it only does:

```ts
setLoading(true)
```

It is complete only when:

```text
user enters text
→ selects voice
→ clicks Generate
→ request validates
→ ElevenLabs request occurs
→ audio returns
→ audio becomes playable
→ generation is persisted
→ History updates
→ loading ends
```

Likewise:

```text
Download
```

is not complete if it only shows a toast.

```text
Play
```

is not complete if it only calls `stopPropagation()`.

```text
Favorite
```

is not complete if the favorite disappears after refresh.

```text
Use Voice
```

is not complete if its callback is empty.

```text
History Filter
```

is not complete if state changes but the displayed records do not.
